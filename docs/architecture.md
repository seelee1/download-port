# 架构与恢复约束

## 组件

- extension/model.js：配置验证、目录选择、路径与文件名处理。
- extension/background.js：串行选择仅下一次目录、保存下载意图、监听完成、连接原生服务、定时恢复。
- extension/popup.html / options.html：共用 simple.js、folders.js 和 simple.css 的文件夹浏览界面。所有文件名与路径用 textContent 渲染。
- native/host.py：有界 native messaging 消息，限定扩展来源与配置 ID，目录选择和任务接口。
- native/core.py：SQLite 队列、跨进程文件锁、验证、提交、删源及恢复。
- native/install.py：按当前用户注册 Chrome／Edge 的原生服务，保留固定扩展 ID。

## 持久化与幂等性

浏览器任务按下载 ID 保存，另有随机 UUID 作为归档 ID。原生任务以扩展来源、浏览器本地 profile UUID、归档 ID 联合隔离。同一 ID 重复提交不会重新复制已完成任务。每个任务保存 sourceSignature、目标快照和复制后哈希；目标目录编辑时生成新的目录注册 ID，避免影响在途任务。

状态：queued → archiving → done；失败转 waiting，达到阈值转 failed。阶段：new → copying → verified → committing → committed → done。独立字段区分工作状态和已完成的文件事务阶段。

SQLite 使用 WAL 与 FULL 同步；每次数据库操作显式关闭连接。原生工作进程使用操作系统文件锁串行处理归档事务，进程崩溃后锁自动释放。连接断开时已开始事务继续完成，后续队列下次连接恢复；不是常驻系统服务。

## 不覆盖与提交恢复

目标临时文件使用任务 UUID 和独占创建。Windows 使用不覆盖目标的 os.rename；若目标已存在，则尝试下一个编号。POSIX 测试分支使用独占硬链接创建（不代表已提供 POSIX 安装支持）。没有使用替换目标文件的 os.replace。

复制完成后校验哈希，提交前记录目标路径与临时文件设备号、文件号。如果提交成功但状态写入前崩溃，重启后用目标的文件身份与哈希确认它确实来自该任务，再决定是否删源。无法确认时保持源文件并报告失败。文件系统不能提供稳定文件身份时可能需要人工处理，不猜测所有权。

源文件在提交前后检查设备号、文件号、大小和修改时间；删除前还检查内容哈希。目录空间不足、源发生变化或身份不明时不自动删源。这里不承诺抵抗同权限恶意进程在每个系统调用间替换文件，也不将应用级同步等同于所有存储硬件的断电保证。

## 浏览器边界

onDeterminingFilename 只处理本工具可接管的普通非隐私下载。先持久化意图，再建议路径。绝对目标采用 Downloads 下暂存目录；不重新发送网络请求，因此没有额外复制登录 Cookie、POST 请求或一次性 URL 的逻辑。

下载完成后检查浏览器安全状态，再请求归档。其他扩展修改的路径、另存为选择到暂存路径以外的文件会被原生服务拒绝。页面没有注入内容脚本，不尝试把当前活动标签页当成来源。

## 未完成的产品能力

按标签页／标签组精确分流、多浏览器主动配置同步、直接写入任意目标盘的网络传输、签名安装器、自动升级和商店发布尚未实现。本版本提供完整的目录管理与归档工作流，但这些能力不在已验证范围内。

## 目录浏览

native/folders.py 校验目录边界并读取当前层，listFolders 每次返回最多 200 个目录。前端缓存最近 100 层，导航时先显示缓存再验证；确认目标时再次检查目录存在。搜索在前端按需遍历，使用序号丢弃被取消请求的旧结果，并明确报告不完整情况。

目录扫描不改变磁盘文件；浏览不改变下载位置，确认后才保存选择。分页是动态读取，不提供磁盘快照；外部修改目录后可能需要刷新。下载目标由用户确认选择，不应用自动分类规则。
